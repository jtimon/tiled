** WIP #5 Configure commands and keybindings in Til for Tiled and tilminal

*** Goal

Let users define commands and keymaps in Til, with the extensibility of Emacs
Lisp or Neovim Lua. Til can be both the application's implementation language
and its configuration/extension language because it supports compilation and
interpretation. Users should be able to change clipboard and terminal input
policy without rebuilding or editing application sources.

This depends on [[https://github.com/jtimon/til/blob/master/issues/open/370.org][Til #370: host program, guest Til]] for live embedding: a running host must be
able to invoke user-defined Til callbacks against its live application state.
Track application-facing APIs, configuration loading and key dispatch here;
coordinate interpreter/runtime embedding requirements with Til #370.
Using the same language does not by itself provide a live embedding API.

*** Current state

- First step implemented: shared headless keymap resolution, named built-in
  commands, bind/rebind/unbind, multi-key prefixes, selection-specific maps,
  minibuffer precedence, explicit forwarding and repeat/text-event policy.
- Tiled loads =~/.tiled/init.til= and tilminal loads =~/.tilminal.til=.
  Tiled now interprets a zero-argument =init()= through TilVm and reads a shared
  startup settings library (see #18). Its guest API exposes options and built-in
  keymap overrides and retained selected-text commands (see #19). Tilminal retains the compiled GUI-child loader and
  =config.commands=. Native Tiled callbacks still use =TiledConfig.commands=;
  broader live guest buffer APIs remain to be implemented.
- Tiled startup needs the matching installed SDK assets and generated native
  binding/library, but no compiler executable or replacement GUI process.
  No live reload is implemented.
- M-x now searches/runs built-in and registered user commands through the same
  executor as keybindings. Effective shortcuts account for selection and prefix
  shadowing. Describe-key reports the actual winning map/command without executing
  input. Both hosts share the discovery model and minibuffer renderer; Tiled can
  inspect an existing prompt without replacing its contents. Headless ASAN and
  GUI discovery checks pass, alongside existing input/prompt/clipboard tests.
- [[file:../../doc/keybindings.org][The implemented API]] and working default configs are documented;
  [[file:../../doc/keybindings.til][the earlier broader API sketch]] remains a proposal.
- Verification: compiled/interpreted =test/keymap.til=; =test/keymap_gui.til=
  uses explicit native Tiled fixtures and tilminal user config, invokes callbacks after startup,
  saves a live edited buffer, changes paste to Ctrl-V, forwards Ctrl-Shift-V,
  overrides prompt cancellation and diagnoses an unknown command. Existing
  clipboard, mapped-input, terminal lifecycle, scrollback and exit GUI checks
  pass. =test/make_clean.til= also verifies scratch cleanup preserves references.

*** First local TilVm integration slice

=src/guest_transform.til= uses only the installed public =std/tilvm= API to
retain a checked =proc(Str) returns Str= guest transform. It passes a copy of
the selected text, applies a successful result through the existing editor
replacement/undo methods, and propagates structured call errors before editing.
The caller owns the VM and keeps it alive until the adapter is destroyed.

=test/guest_transform.til= compiles an ASAN host, then runs it in a private
directory with private HOME and empty PATH. That already compiled host creates
its guest and imported helper. Tests cover signature rejection, retained
captures/repeated calls, guest symbol rebinding, Unicode text, one-step undo,
panic/exit recovery with unchanged editor text/selection, named key resolution,
and result/diagnostic lifetime after callback and VM teardown. The test passed.
The SDK root is an explicit argument, not a machine-specific source dependency.

The text-command adapter now also backs the live GUI guest registry. Production
startup settings and registration descriptors use a shared library. See
[[file:../../doc/tilvm.org][the prototype contract and next-upgrade findings]].

*** Remaining Til dependency and integration findings

The installed SDK now supplies checked =lookup=, retained =TilVmCallback.call=
and scalar/string interchange. It also permits prebuilt native-library imports,
providing a generated-binding route to shared functionality without dynamic
host-function registration. Passing the existing mutable =TiledConfig=/
=EditorState= records directly through callbacks still needs an explicit type/
ownership contract. Tiled's settings milestone uses a zero-argument init instead
of passing that native record. Tilminal retains its compiled startup loader.

*** Shared native library proof

=test/guest_shared.til= builds a native Til text-store fixture and an ASAN host
using Tiled editor/transform code. Generated bindings reference the same explicit
shared-object path for the compiled host and both TilVm guests. With private
HOME and empty PATH, the test passed shared state visibility, Unicode string
ownership, missing-library retry, native throws propagation and VM teardown.
Native calls continue working after both VMs are destroyed. The fixture is not
a second editor model or a production library split.

The same verification also rebuilt both GUI hosts, reran the earlier ASAN guest
transform test, and passed ASAN =unicode=, =unicode_editing=, =undo_tree=,
=keymap=, =command_discovery=, =session_model= and =tabs=; interpreted
=unicode_editing=; and Xvfb =unicode_gui=, =keymap_gui= and =session_optin_gui=.
The build driver regenerated the compiler dependency record automatically.

The shared startup API is now used by the actual Tiled executable. Next: choose
the smallest live editor API with one owner of buffer/undo
state. Avoid a static host copy plus a guest-loaded dynamic copy, and do not
promise that editor undo rolls back arbitrary native side effects.

*** Live selected-text command registration

=tiled_text_command(name, symbol)= now registers public guest procedures matching
=proc(Str) returns Str=. After init, typed handles are validated and stored in
=EditorGuestCommands=; the caller keeps their VM alive through the editor loop
and destroys handles before the VM. The normal keymaps/M-x discover and invoke
them, with nonempty-text-region restrictions and error recovery. No capturing
native EditorAction bridge is used.

The scoped implementation and verification are tracked in #19. General buffer
operations, runtime registration and hot reload remain open; the selected-text
contract intentionally exposes copied text rather than native editor pointers.

*** Earlier native command composition findings

The small adapter exposed three additional composition problems on installed
Til =fcbe4e79a=; the TilVm session should investigate them before native command
registry integration:
- Capturing an =EditorGuestTransform= by value in an =EditorAction= closure
  generated a call to missing =EditorGuestTransform_clone= (C compilation error).
- Vector indexing directly inside a procedure throwing =TilVmError= generated
  an assignment to =_err_kind= rather than its pointee (C compilation error).
  The adapter takes its host snapshot in a non-throwing helper instead.
- Borrow-capturing an adapter in an ordinary native command and registering it
  through =EditorCommands.command= compiled, but ASAN found heap-use-after-free
  on invocation: the closure box was freed after registration while the registry
  retained its pointer. The working probe dispatches a typed guest handle after
  key resolution, without routing it through a captured native =EditorAction=.

The earlier stored-procedure effect/mutability limitations have been fixed in
Til; existing native wrappers still contain their older explicit effect/local
callable spelling. No compiler files were changed in this phase.

Startup integration also exposed two compiler edges: a nested record default
was emitted as a positional aggregate in generated Til bindings, and rethrowing
a caught error emitted an unknown-statement placeholder in C. The startup API
uses fully populated snapshots from a native getter (no nested record default
in the exported type), and the loader returns an owned optional error to its
caller. ASAN and actual-startup tests verify errors are reported, staged values
are reset, and a failed init never silently launches with defaults.

*** Scope

- Load standalone terminal configuration from =~/.tilminal.til= and extend
  Tiled's existing =~/.tiled/init.til= configuration entry point.
- Expose named built-in commands and registration of user-defined Til
  commands/callbacks. Bindings should refer to commands rather than duplicate
  their implementations. Imported user modules should also be usable.
- Support binding, rebinding and unbinding keys, multi-stroke prefixes, and
  distinct text, terminal, minibuffer and other contextual keymaps. Specify
  precedence, mapped modifiers, repeat behavior and text-event consumption.
- Make Emacs/CUA preferences, copy/cut/paste, selection-aware Ctrl-C,
  Ctrl-G cancellation, terminal forwarding and host-prefix handling
  configurable. Keep the current behavior as the initial default profile.
- Allow explicit forwarding of keys to terminal children so user mappings
  can resolve conflicts between host commands and foreground applications.
- Define callback access to focused buffers/views, selections, clipboard,
  sessions and application commands, with clear ownership/lifetime rules.
- Define startup evaluation, reload behavior, useful diagnostics and recovery
  from failed configuration/callbacks. Specify how host state survives reload.
- Choose and document the integration with Til's embedding API. Evaluate
  interpreted callbacks and compiled extension modules against the same
  host-facing command interfaces; distinguish interim startup configuration
  from live extensibility.

*** Acceptance checks

- Change terminal paste from Ctrl-Shift-V to Ctrl-V in user configuration,
  without rebuilding the host, and explicitly retain a way to forward Ctrl-V.
- Configure Emacs and CUA clipboard bindings and selection-dependent behavior
  in editable buffers and terminal panes.
- Register a user Til command, bind a prefix sequence to it, and operate on
  the focused pane's live state rather than a copied configuration snapshot.
- Verify context precedence, split-pane isolation, remapped modifiers,
  repeats, character-event suppression, error handling and reload semantics.
- Provide working default/sample configurations and document the supported
  interpreter/compiler/runtime compatibility requirements.
