** OPEN #15 Extract locally validated Unicode support to Til std

*** Local implementation completed

The local-first phase is implemented and verified. =lib/libunicode/unicode.til=
provides UTF-8 encoding/validation/streaming decode and Unicode 17.0 extended
grapheme boundaries without GUI or native dependencies. Versioned property data,
license and the official conformance corpus are checked in; the Til generator
in =examples/unicode_tables.til= regenerates them. Balanced range lookups avoid
the slow interpreted linear-table scan encountered during development.

Editor and minibuffer input now accepts Unicode scalar events. Movement,
selection, deletion, label truncation, logical columns and recovered cursor
positions respect grapheme boundaries. Undo/checkpoints remain byte-based.
The GUI loads encountered font glyphs and measures/draws zero-advance combining
marks consistently. Full shaping, bidi layout and font fallback are separate
rendering work; see =doc/unicode.org= for the supported behavior and limits.

Verification:
- Both hosts built with =./make.til=.
- =test/unicode.til=: all 766 official Unicode 17.0 grapheme cases, forward,
  backward and byte-position clamping, plus malformed/truncated UTF-8; compiled
  ASAN and interpreted runs passed.
- =test/unicode_editing.til=: editor/prompt regions, deletion, undo, columns,
  CRLF and saved-point recovery passed compiled ASAN and interpreted.
- ASAN regressions: =editor_selection=, =undo_tree=, =buffers=, =layout=,
  =keymap=, =command_discovery=, =session_model= and =tabs= passed.
- Xvfb: =unicode_gui=, =command_discovery_gui=, =terminal_font_gui=,
  =clipboard_gui=, =session_optin_gui= and =undo_gui= passed. Unicode GUI tests
  use private HOME/Xvfb fixtures, real character events, independent glyph
  pixel comparisons, clipboard/undo, Unicode filenames and both hosts' prompts.

Remaining: coordinate the eventual Til std API/extraction, reuse the local
tests, and consolidate terminal/editor primitives against the installed API.
No Til repository or system installation was changed in this phase.

*** Local-first decision

Implement and validate the reusable primitives locally first, as requested.
Move them to Til std only after the editor integration is working; no parallel
compiler changes or repeated cross-repository handoffs are required now.
Preserve byte-offset storage, undo and checkpoints while making interactive
editing respect Unicode grapheme boundaries. Track the later extraction here.

*** Initial source inventory (before local implementation)

- =lib/libterminal/text.til=: UTF-8 scalar encoding/streaming decoding and
  Unicode 17.0 scalar terminal-width tables. Decoding distinguishes incomplete
  chunks from final input and replaces malformed sequences while making progress.
  Preserve the Unicode/wcwidth provenance and license notices on extraction.
- =src/editor_model.til=: =text_next=/=text_previous= skip continuation bytes;
  these are byte-boundary helpers, not validation or grapheme segmentation.
  Cursors, selections, undo deltas and saved positions currently use byte offsets.
- =src/minibuffer.til= and =src/minibuffer_view.til=: editing and truncation have
  byte-oriented paths. =src/editor.til= and =src/command_discovery.til= currently
  restrict typed character events to ASCII, despite accepting UTF-8 file/paste data.
- =test/terminal_model.til=, =test/terminal_input.til=,
  =test/editor_selection.til= and =test/undo_tree.til= supply initial consumer
  cases. Current scalar-width handling explicitly does not provide emoji/ZWJ
  shaping; renderer/font policy must remain distinct from Unicode primitives.

*** Decisions for the Til session

1. Audit existing Til APIs and issues first. Propose a reusable =std/= module
   for validation, scalar encoding/decoding (including streaming), iteration and
   boundary discovery, with explicit malformed-input/error/replacement policy.
2. Decide whether Unicode APIs extend =Str=, operate on explicit views, or need
   a separate validated UTF-8 type. Keep the question open. An additive API that
   preserves existing byte offsets is a sensible first step; silently changing
   =len=, indexing or slicing would break editor/FFI/persistence consumers.
3. Distinguish bytes, scalar values and extended grapheme clusters in names and
   contracts. Specify the complexity of indexing and offset conversion; Unicode
   character indexing must not imply constant-time byte indexing.
4. Plan grapheme segmentation and versioned Unicode property data separately
   from scalar decoding. Consider terminal-cell width as a reusable policy layer
   (ambiguous width, controls, emoji/variation selectors), not a universal
   string length or graphical text measurement. Normalization/case folding can
   follow as explicitly scoped work rather than hidden string conversions.
