** OPEN #10 Add an optional familiar menu bar backed by named commands

Offer a discoverable menu bar, like Emacs and conventional desktop applications,
for users who do not yet know the keybindings. Make it easy to hide as users
become comfortable with keyboard commands, and easy to show again.

*** Scope

- Group available actions under familiar headings such as File, Edit, View,
  Buffers/Tabs, Terminal, Configuration and Help/About. Adapt the menu to each
  host: Tiled has editor/workspace actions; tilminal has terminal/tab actions.
  Exact group names and initial visibility can be chosen during implementation.
- Use the same named command executor as keymaps and future M-x discovery;
  menu clicks must not synthesize keyboard shortcuts or duplicate operations.
- Display current configurable shortcuts beside actions, rather than hard-coded
  labels that become wrong after rebinding. Show relevant enabled/disabled,
  checked and context-dependent state, including text versus terminal selection.
- Support pointer and keyboard navigation, mnemonics where appropriate, Escape
  cancellation, focus restoration and small-window/overflow behavior. Menu
  navigation must not leak keystrokes to an editor buffer or terminal child.
- Provide a named visibility-toggle command and Til configuration for visibility
  and menu definitions/extensions, referencing registered commands. Hiding the
  bar must leave all actions and a way to restore the bar available by keyboard.
- Expose actual implemented actions: opening the user configuration, documentation
  and version/About information are useful; do not imply that unimplemented
  settings, live reload or other planned features already work.
- Decide between host-drawn and platform-native menu adapters without moving
  command definitions or state policy into platform-specific UI code.

This is the application's own menu surface. Managing another application's
menu in future desktop/WM mode is a separate platform integration question.

*** Acceptance

- Invoke the same action from a keybinding and a menu and observe identical
  focused-buffer/session behavior, including dirty-buffer and live-child flows.
- Rebind a command in Til and verify the displayed shortcut follows it.
- Exercise keyboard/mouse navigation, cancellation without input leakage,
  context-sensitive availability, visibility toggling and resizing.
- Show useful menus in both hosts without requiring an embedded interpreter;
  compiled startup configuration is sufficient for the first milestone.
