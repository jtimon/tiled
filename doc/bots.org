* Agent instructions

** Working style

- Be brief and direct. Carry out the requested work; ask in plain chat when
  a consequential choice is genuinely unclear.
- Keep changes focused, follow existing patterns, and fix causes rather than
  hiding errors. Read actual build/test failures before changing course.
- Preserve unrelated work. Commit completed, tested tasks automatically;
  the user handles pushes. Track each task in an issue, even when opening
  and closing it in the same commit.
  Do not create branches/worktrees or rewrite history without being asked.

** Build and verification

- Build both hosts with =./make.til= (installed =til run=, no GNU Make or
  compiler bootstrap). See [[file:build.org][build instructions]]
  and [[file:terminal.org][terminal tests]]. Run checks relevant to the change and report results.
- Prefer tests written in Til. Keep scratch files and logs in =tmp/=;
  =gen/= and =bin/= are generated outputs, not files to edit by hand.
- =./make.til clean= removes =bin/=, =gen/= and =tmp/=. Keep reference clones
  in Git-ignored =.inspirations/=, which clean preserves.
- Run long builds/tests in the foreground, one at a time. Documentation-only
  work does not need an application rebuild.
- Til development is at =~/code/jt/til/=. Consult it for compiler/runtime
  dependencies and suggest concrete priorities; distinguish installed =til=
  from that checkout's =bin/til=. Read its own instructions before editing it.

** Issues

- Follow [[file:../issues/process.org][the issue workflow]]. The next-number counter is
  =issues/NEXT_ISSUE.txt=: read it before creating an issue, use that number,
  then increment it. Never guess or reuse numbers.
- Create =issues/open/N.org= with =# priority: high|medium|low=,
  =# category: <category>=, and =** OPEN #N Title=.
- Mark started work =WIP=. When fully resolved, move the issue to
  =issues/fixed/=, mark it =FIXED=, and record the change and verification.
  Cancelled issues go in =issues/cancelled/= with a reason.
- Keep issue changes aligned with the requested work; ask before unrelated
  tracker reorganization or priority changes.
- Regenerate =issues/summary.org= with =til interpret make.til summary= after
  issue changes. Do not hand-edit the generated summary.
