* Tilminal and the shared terminal component

[[file:../README.org][Tiled]] | [[file:build.org][Build and run]] | [[file:architecture.org][Architecture]]

Tilminal is a standalone terminal emulator developed in this repository.
Tiled embeds the same terminal component in its panes through =C-x t=.
There is one terminal implementation and two hosts. See
[[file:configuration.org][terminal-buffer commands]] for switching, mirrored views and lifecycle policy.

** Running

Build both applications with installed Til (see [[file:til-dependency.org][Til build dependency]]):

#+begin_src sh
til interpret make.til
./bin/tilminal
./bin/tilminal 'printf "hello\n"'
#+end_src

The default is an interactive =$SHELL= (=/bin/sh= if unset), or =COMSPEC=
on Windows. The optional argument is one shell command. The shell inherits
the caller's working directory; =cd= and shell variables persist. After a
command exits, its final screen stays visible and the title reports its exit
status. Escape is terminal input. Closing the window closes the session.

Standalone tilminal now supports [[file:tabs.org][multiple terminal tabs]]. Ctrl-Shift-T creates
one, Ctrl-PageUp/PageDown switches, and Ctrl-Shift-B hides/shows the bar. Hidden
tabs continue pumping output. Closing a tab ends its child; closing the window
ends all its tabs. Embedded terminal buffers participate in Tiled's buffer tabs.

Standalone tilminal [[file:sessions.org][saves workspace/output checkpoints by default]];
Tiled requires an explicit opt-in through =~/.tiled/init.til=. Standalone
restoration starts a fresh shell in the last known directory; embedded
terminals restore as labelled output buffers. Neither reattaches running jobs.
Use =--session NAME=, =--fresh= or =--no-session= to control persistence.
One-shot commands leave the default interactive checkpoint alone unless given
an explicit session name.

Fonts are resolved through =fc-match monospace= from fontconfig, as in Tiled;
install fontconfig and a monospace font. Both hosts default to 28-pixel glyphs.
Embedded terminals inherit Tiled's configured =font_path= and =font_size=;
standalone tilminal exposes those same settings in =~/.tilminal.til=.
Rendering uses the editor's filtering and line-height convention, without extra
inter-character padding. Glyph bearings are clipped at the pane boundary rather
than each individual cell. Font metrics also determine PTY rows/columns, input
hit-testing and tilminal's command prompt geometry.
Neither the imports nor the default font path need a Til source checkout, and
launching from =bin/= works without changing the shell's cwd.

** Scrollback

Both hosts retain up to 2,000 rows of primary-screen output. Use
=Shift+PageUp= / =Shift+PageDown= to move by a page (with one row of overlap),
or the mouse wheel to move three rows per notch. In Tiled, keyboard scrolling
uses the focused pane and the wheel uses the pane under the pointer without
changing focus. Each split has its own scrollback position. The title or
pane mode line shows the offset while reviewing history, and the live cursor
is hidden.

New output keeps a scrolled view anchored, including while its buffer is
hidden. If those rows are evicted, the view clamps to the oldest retained
row. Scrolling down to offset zero follows live output again. Typing or
sending another non-modifier key to the child also returns that view to live;
Tiled's host prefixes/prompts do not move other views. Entering an alternate
screen returns views to live output. Alternate-screen output never enters
history, and Shift+PageUp/PageDown is passed to the application there.

History records full-screen upward scrolling (linefeeds, wrapping, and CSI S),
not partial scrolling regions, reverse scrolling, deleted lines, or erased
screens. CSI 3 J clears primary history without erasing the live page; CSI 2 J
erases the page without clearing history. Alternate-screen CSI 3 J leaves
primary history alone. RIS clears history; process exit retains it.

Historical rows retain their original width, style and Unicode cells. Resize
clips/pads them without reflow; expanding again reveals retained columns.
The live grid keeps its existing top-left crop/pad resize policy: rows cropped
by a height reduction are not added to history. A clipped wide glyph is blank
rather than a half glyph. The library can change/disable the history limit;
there is not yet a host configuration setting for it.

** Selection and clipboard

The bindings below are defaults, configurable through [[file:keybindings.org][commands and keymaps]].
Standalone configuration is =~/.tilminal.til=; embedded panes use
=~/.tiled/init.til=.

=M-x= now opens a host command palette in either terminal host. Use
=M-x describe-key= to inspect input routing without sending the keys to the child.
These prompts use the host's minibuffer bindings; closing them returns input
to the original pane. Ctrl-H remains terminal input; the text-only =C-h k=
binding does not intercept it in terminals.

Drag with the left mouse button to select terminal cells, including printed
output and scrollback. Selection is linear and independent per pane. Wheel
or page navigation can move through history while selecting; dragging past
the pane edge clamps to the edge rather than automatically scrolling.

| Key             | Terminal action                                      |
|-----------------+------------------------------------------------------|
| C-c             | Copy an existing selection and clear it; otherwise forward Ctrl-C |
| C-S-c or M-w    | Copy selection and clear it                          |
| C-g             | Clear selection; otherwise forward Ctrl-G            |
| C-S-v or C-y    | Paste the system clipboard                           |
| C-v             | Forward Ctrl-V to the child                          |

Here =M= is Alt/Meta and =S= is Shift. There is no new interrupt prefix:
with a selection, two Ctrl-C presses copy first and then forward Ctrl-C.
Tiled's active host prefixes/prompts still take priority over these bindings.
Terminal cut/edit commands remain owned by the shell or foreground program;
the host does not delete displayed cells to simulate editing its input.

Copying preserves wide and combining Unicode text, omits continuation-cell
placeholders, joins soft-wrapped rows, and inserts newlines at hard row
boundaries. Trailing padding is trimmed at hard boundaries, including empty
lines. Copy reflects visible columns at the current width. New child output,
resize, reset/history clearing or screen changes invalidate selection; ordinary
scrollback navigation does not. This intentionally conservative first version
can be revisited alongside configurable bindings and richer selection modes.

Paste returns the receiving pane to live output. DEC mode =2004= enables
bracketed paste: the payload is enclosed in CSI 200~ / CSI 201~ and retains
linefeeds. Otherwise line breaks are sent as carriage returns. Clipboard CRLF
and CR are normalized; embedded NUL and ESC are removed from text payloads.
Clipboard access is host-owned through raylib; the library owns encoding and
selection state. Only the system clipboard is used, not an Emacs kill ring or
X11 PRIMARY/middle-button selection.

** Alternate screens and terminal profile

The model supports DEC modes =47=, =1047=, =1048= and =1049=. Primary and
alternate pages retain independent cells, cursor/save state and scrolling
margins. =47= preserves both pages; =1047= clears the alternate page on
leaving; =1048= saves/restores the cursor without switching; =1049= saves
the primary cursor, clears/homes the alternate page and restores the primary
cursor on return. Repeated =1049= entry/exit is idempotent, not a nesting stack.
Saved state includes rendition, character sets, origin/wrap and pending wrap.
Resize updates both pages and repairs clipped wide cells. RIS resets both;
child exit keeps the final active page visible.

On POSIX, both hosts select =TERM=tilminal= with a child-local =TERMINFO=
pointing at =gen/terminfo/=. The build needs ncurses =tic= and compiles
=lib/libterminal/terminfo.src=. This minimal profile inherits =vt100= and
adds alternate-screen/cursor-visibility capabilities; it does not advertise
full xterm compatibility. The generated absolute database path must remain
available at runtime, including when launching from another directory.
Rebuild after moving the checkout. Core-only consumers default to =vt100=
and can select/package their own profile through =session.set_profile=.

** Source ownership and migration

Migrated from Til commit =40eb0682e= (present in =b444d7223=), including its
terminal tests. [[file:../lib/libterminal/LICENSE.txt][The original MIT license]] and the Unicode/wcwidth attribution
in =text.til= are retained. Tiled's old =examples/tilminal.til= command runner
has been replaced by the persistent-session implementation.

- [[file:../src/tilminal.til][src/tilminal.til]]: standalone entry point/config loading; [[file:../src/tilminal_app.til][tilminal_app.til]] owns
  the window, shell startup and lifecycle.
- [[file:../lib/libterminal/session.til][session.til]] / [[file:../lib/libterminal/session.c][session.c]]: PTY/ConPTY transport, child ownership,
  input queuing, resize, final-output draining and teardown.
- [[file:../lib/libterminal/model.til][model.til]]: terminal screen grid, incremental escape parser, cursor,
  scrolling regions, rendition, keypad modes and query replies.
- [[file:../lib/libterminal/text.til][text.til]]: incremental UTF-8 and Unicode 17 scalar-width tables.
- [[file:../lib/libterminal/input.til][input.til]]: headless encoding of host-supplied ordered key/text events.
- [[file:../lib/libterminal/terminal.til][terminal.til]]: host-owned session, screen and input state; explicit
  =start=, =resize=, =pump=, =event= and =close= operations.
- [[file:../lib/libterminal/view.til][view.til]]: glyph resources and rendering a supplied screen/viewport.

The terminal component lives in =lib/libterminal/=, separate from the
application sources in =src/=. Its internal imports and native bridge link
are relative to that directory. Both hosts and terminal tests consume its
selected generated API, with static linking by default and shared/source
comparison modes. The raylib view remains a source adapter. See the
[[file:../lib/libterminal/README.org][library build, installation and ownership contract]] and [[file:terminal-library-benchmark.org][measurements]]. Hosts create the
window and own the event loop. Til supplies core/std, mode gui and its runtime
ABI; application-specific development and
tests belong here. Compiler regressions formerly bundled with the terminal
tests stay in Til: =test/link_objects.til= and =test/vec_clone_abi.til=.

Both hosts use [[file:../src/window_input.til][window_input]] for ordered events. Character events retain
their mapped modifier flags, including Alt text. Terminal input processing
does not poll raylib queues, reorder text before functional keys, or sample
modifiers later in the frame. A renderer neither pumps nor resizes a session.
Rendering accepts an explicit viewport and clips wide cells at its boundary.

Pass the installed compiler's absolute path to the session test if it is
installed elsewhere. The test builds its helper under =tmp/=, exercises the
real Til REPL and keeps its history under =tmp/=. It covers independent
sessions, terminal detection, argv quoting, resizing, partial input/output,
explicit startup failure, child exit, persistent shell cwd/environment and
foreground Ctrl-C on POSIX.

The GUI test needs Linux/X11, Xlib/XTest, =xwininfo= and =xvfb-run=. It launches
the actual =bin/tilminal= with =bin/= as cwd, waits for a real window, types
=ls= against a fixture directory and compares the rendered output pixels
against a reference row rendered with the same font. The marker filename
does not appear in the typed command, so echoed input cannot satisfy the
assertion; a blank reference is rejected too. It then requests a normal
window close and requires exit status zero. It also sends burst text followed
immediately by Enter and remaps Control with xmodmap while running, verifying
that a fast Ctrl-C interrupts a foreground job and returns to the shell.
A second case verifies rendered
wide/combining Unicode output, retained final screen and one-shot status.
The test, pixel comparison and window-close handling are written in Til
using X11 FFI declarations. No C test helper, OCR dependency or test-only
application export is used. Failed checks
attempt an ImageMagick screenshot at =tmp/terminal-gui-failure.png=.

Selection checks cover forward/backward ranges, Unicode, soft wraps across
history/live rows, blank lines, wide-wrap padding, invalidation and clipboard
key routing. Compiled/interpreted installed consumers exercise the API. The
Linux/X11 clipboard GUI test verifies highlighting, actual clipboard text,
independent terminal split selections, Ctrl-C/C-g forwarding and actual
bracketed-paste bytes received by a raw PTY child. It also checks mouse/mark
selection, Emacs/CUA clipboard shortcuts and saving in editable Tiled buffers.

The font check configures a different monospace font at 36 pixels in both hosts
and compares actual terminal pixels with the editor's ordinary DrawTextEx path.
It also checks the resulting PTY dimensions. Startup applies window/font metrics
before replaying saved terminal output, so a larger font does not crop text via
an initial resize from the model's default 80-column grid.

The scrollback suite covers bounded eviction, output anchoring, independent
viewports, page-key routing, original-width resize, wide/combining characters,
rendition, input splits, alternate-screen exclusion and history reset. It
passes compiled source/static and interpreted builds, plus installed compiled
and interpreted consumers. GUI checks in both hosts cover rendered history,
page/wheel navigation and return to live; Tiled additionally checks hidden
buffer output and independent split positions.

The alternate-screen suite covers cursor banks, repeated transitions, hidden
page resize, wide cells, cloning, input splits, EOF and reset. It passes in
source/static/shared builds and installed compiled/interpreted consumers.
Real PTY and GUI tests use =less=, =vim.tiny= and =top=, checking entry, resize,
quit and restored shell output in both hosts. They require these programs
and =tput=. This procps =top= does not request an alternate screen itself;
its test explicitly wraps it in =tput smcup= / =tput rmcup=.

The migrated model passed interpreted, compiled and ASAN checks on Linux.
The session suite passed normal and ASAN runs; GUI acceptance passed with
normal binaries. Native Windows ConPTY and macOS PTY runs remain unverified.

The embedded test verifies real pixels, split/window resize reaching the
child, hidden output larger than a PTY buffer, text/terminal input isolation,
remapped Control, Escape/Ctrl-G forwarding, literal Ctrl-X, kill/exit
cancellation, normal child exit, slot reuse, process reaping and startup
failure recovery. Shared helpers and assertions are written in Til. The
embedded workflow also passed with an ASAN editor and GUI leak detection
disabled for the existing Mesa/LLVM leak noise; this is an invalid-access
check, not a leak-free GUI claim. Headless ASAN checks retain leak detection.

** Follow-ups

- Reduce model/interpreter and test-build cost while retaining coverage.
- Validate native ConPTY on Windows and PTYs on macOS, including frontend
  font availability. Cross-compilation alone is not runtime validation.
- Refine selection persistence during output, word/line/rectangular selection,
  edge auto-scroll and configurable clipboard bindings after using the first
  linear-selection implementation. Broaden terminal compatibility beyond the
  current VT100-derived profile.
- Validate packaging beyond Linux, stabilize/version the experimental library
  ABI and split repositories as tracked in [[file:../issues/open/4.org][#4]].
- Investigate Kitty graphics and other application-supplied inline graphics
  after the terminal/session integration. [[file:../issues/open/3.org][Tiled #3]] carries the full design
  discussion transferred from Til #408 and tracks subsequent implementation.
