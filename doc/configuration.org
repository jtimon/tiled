* Startup and user configuration

[[file:../README.org][Tiled]] | [[file:build.org][Build and run]] | [[file:keybindings.org][Keybinding design]]

** Default startup

=tiled= checks =$HOME/.tiled/init.til= at startup. If it is absent, it prints:

#+begin_example
No ~/.tiled/init.til file found; using defaults.
#+end_example

It then opens an empty =*scratch*= buffer in the left half of the current
monitor, using its full height. Scratch has no filename; =Ctrl+S= opens the
save dialog. =Ctrl+O= opens an existing file.
A filename passed on the command line opens that file instead of scratch.

Holding an arrow key, Backspace, Delete or Enter repeats the action using
the desktop's keyboard repeat delay and rate. Held letters repeat through
the normal text-input stream. Home and End also accept repeat events;
command shortcuts such as save and open respond only to the initial press.

=C-x C-c= requests exit: press Ctrl+X, then Ctrl+C. Shortcuts use the OS-mapped
modifiers captured with each key press, including Control remapped with
=xmodmap=. =C-g= cancels a recognized pending =C-x=; an unrecognized
continuation is consumed and cancels the prefix.

** Exiting with unsaved edits

=C-x C-c=, Escape in a text pane outside a prompt, and the window's close
button check every loaded buffer, including hidden ones. Tiled exits
immediately if there are no modified text buffers or live terminal sessions.
Otherwise the minibuffer asks about each once, showing its name and progress.
Modified text buffers offer:

- =save=: save this buffer and continue to the next modified buffer.
- =discard=: continue without saving this buffer.
- =cancel=: abandon the exit attempt and return to editing.

Type the choice and press Enter, or select it with the arrows. Empty input
defaults to =cancel=. =C-g= or Escape also cancels. Repeated close-button
requests do not restart an active confirmation.

Discard decisions apply only to that exit attempt. If you cancel at a later
buffer, earlier discarded buffers still contain their unsaved edits and
remain marked modified. Successful earlier saves remain saved. Panes, focus
and cursor positions are preserved while checking hidden buffers.

Saving an unnamed scratch buffer uses Til's =mode gui= Save file dialog.
Cancelling that dialog, or failing to save a file, stops the exit attempt
and returns to editing with the buffer still modified. Save failures display
an error in the status area, including open, write and close/flush failures.
The same recoverable save handling applies to =C-s= and =C-x C-s=.
Live terminal sessions also participate in this sequence: they offer
=terminate= or =cancel=, rather than save/discard. Termination is deferred
until the entire exit sequence is accepted; cancelling later keeps all
sessions running. Exited terminals require no confirmation.

** Internal tiling

These commands operate on views inside the existing Tiled window:

| Binding | Action                                  |
|---------+-----------------------------------------|
| C-x 2   | Split the focused view top/bottom        |
| C-x 3   | Split the focused view side by side      |
| C-x o   | Focus the next view in layout order      |
| C-x 0   | Close the focused view, keeping at least one |
| C-x 1   | Keep only the focused view               |
| C-x C-f | Open a file in the focused view          |
| C-x C-s | Save the focused view's buffer           |

Press Ctrl+X, then the continuation. In text panes, =Ctrl+O= and =Ctrl+S=
remain available for open/save. Clicking a pane changes focus. A split
initially displays the same buffer in both views; text views have independent
cursor/scroll state, while terminal views mirror one session's screen.
Opening another file affects only the focused view; closing views keeps
their buffers. See [[file:architecture.org][the layout model]] for details.

Very small views refuse further splits. =C-x 5= and additional OS windows
are deferred.

** Buffers and the minibuffer

| Binding | Action                                      |
|---------+---------------------------------------------|
| C-x b   | Switch the focused pane to a loaded buffer   |
| C-x C-b | List loaded buffers and select one           |
| C-x k   | Kill a buffer, defaulting to the current one |

These commands open a minibuffer at the bottom of the window. Type any part
of a buffer name or filename to filter the choices (case-sensitive). Up/Down
select a match, Tab completes its name, and Enter accepts the highlighted
choice. Shift+Tab selects the previous match. Left/Right, Home/End,
Backspace and Delete edit the prompt. =C-g= or Escape cancels it without
changing the document. Mouse clicks do not change the target pane while a
prompt is active.

An empty =C-x b= followed by Enter selects that pane's previous buffer, or
another loaded buffer if it has no history. Switching restores the pane's
own cursor and scroll position for that buffer. Split panes inherit the
existing history, then maintain independent positions; hidden positions
also track shared edits made in another pane.

The buffer list shows =>= for the current buffer, =*= for unsaved edits,
and the filename (=[no file]= for scratch). Files sharing a basename are
identified by their full paths. Long names/paths are displayed with a
leading ellipsis, preserving their ends; completion inserts the full name
in the minibuffer. A query with no matches stays open with an explanation;
it does not create a new buffer. Open files with =C-x C-f= or =Ctrl+O=,
which use Til's =mode gui= file dialog.

=C-x k= asks which buffer to kill. A modified buffer requires typing =yes=
and Enter to discard its edits; =no=, =C-g= or Escape cancels. Empty input
and a single =y= do not confirm. Killing never writes or deletes the file.
If the buffer is displayed in several panes, each switches to another live
buffer while keeping the layout. Killing the last buffer creates an empty
=*scratch*= buffer. This is distinct from =C-x 0=, which closes just a view
and keeps its buffer.

** Terminal buffers

=C-x t= creates a new persistent shell in the focused pane, named
=*terminal-1*=, =*terminal-2*=, etc. It uses =$SHELL= (or =COMSPEC= on Windows)
and inherits Tiled's working directory/environment. =C-x b= and =C-x C-b=
include terminals, showing running or exited status. Terminal text uses the
same font path as the editor, rendered at the terminal's current 20-pixel size.

Within a terminal, =C-x= is Tiled's command prefix: splitting, focus, buffer
switching, open, kill and quit commands work as in text panes. =C-x C-x=
sends a literal Ctrl+X to the child. Other keys, including Ctrl+C, Ctrl+G,
Ctrl+S, Ctrl+O and Escape, belong to the terminal when no host prompt/prefix
is active. =C-g= cancels a pending host prefix or minibuffer. =C-x C-s=
reports that a terminal cannot be saved as a text file.

On the primary screen, =Shift+PageUp= / =Shift+PageDown= navigate scrollback;
the mouse wheel scrolls the pane under the pointer without changing focus.
History retains 2,000 rows, with independent positions in split panes.
Typing returns only the receiving pane to live output. New output keeps
history views anchored until their rows are evicted. The mode line shows
the scrollback offset. Alternate-screen applications receive the page keys
normally and do not contribute to shell history. See [[file:terminal.org][scrollback semantics]].

Splitting a terminal mirrors the same session instead of starting another
shell. The focused pane sets its terminal size; otherwise the first visible
pane sets it. Other panes display their own history/live viewport clipped to
their bounds.
Hidden sessions retain their last size and continue processing output.
=C-x 0= closes a pane while retaining its buffer/session.

=C-x k= requires =yes= confirmation to terminate a running terminal buffer;
=no=, =C-g= or Escape cancels. Accepting kills that session in every view,
releases its native/graphics resources, and displays another buffer in the
affected panes. A child that exits normally leaves its final screen and exit
status available until the buffer is killed. Shell startup failures appear
as status messages and leave the existing editor buffer usable.

** Init file

[[file:../defaults/init.til][defaults/init.til]] is the working configuration to copy when ready.
From the repository root:

#+begin_src sh
mkdir -p ~/.tiled
cp defaults/init.til ~/.tiled/init.til
#+end_src

It defines =init(mut config: TiledConfig)=, which runs before the editor
opens. The supported fields are =width=, =height=, =maximized=, =tile_left=, =scratch_text=,
=initial_file=, =font_path= and =font_size=. A command-line filename takes
precedence over =initial_file=. If neither specifies a file, Tiled opens scratch.
Errors in an existing init file are reported and stop startup rather than
silently loading defaults. =-v= and =--version= bypass configuration and GUI
startup.

The separate [[file:keybindings.til][keybindings.til]] is a [[file:keybindings.org][future keybinding API sketch]], not
the working startup configuration.

** Window size

=tile_left= defaults to =true= and =maximized= to =false=. Tiled initially
fits its outer frame into the left half of the current monitor's usable
work area, accounting for reserved panels, title bars and window borders.
The client area is reduced by the decoration sizes so the bottom minibuffer
and exit prompt remain on-screen. This places Tiled's own OS window; it
does not split the editor into multiple internal views.

=maximized= takes precedence when enabled. With both options set to =false=,
=width= and =height= specify the initial window size: the built-in fallback
is 800x600, while =defaults/init.til= uses 1000x700. The window remains
resizable and movable by the surrounding desktop.

** Font

By default, Tiled uses the system's =monospace= font, resolved with
=fc-match= from fontconfig, with =font_size= set to =28= pixels. On the initial
development machine this selects DejaVu Sans Mono. Set =font_path= to a
TrueType/OpenType font file to use a specific font without fontconfig:

#+begin_src til
config.font_size = 32
config.font_path = "/usr/share/fonts/truetype/dejavu/DejaVuSansMono.ttf"
#+end_src

Font size must be positive. Text, cursor placement, line numbers and the
status bar use the loaded font's measurements. The font is rasterized at
the requested size rather than scaling raylib's default bitmap font.

Change =config.font_size= in =~/.tiled/init.til= and restart Tiled to apply
it. Both the built-in fallback and [[file:../defaults/init.til][defaults/init.til]] use 28 px, so the
larger font also applies before you create a user configuration.

For reference, [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Fonts.html][Emacs defaults to a 10-point monospace font]] on graphical
displays. Tiled's current size setting is in pixels, not points.

** Automatic backups (planned default)

Tiled should create backups automatically by default, like Emacs. On the
first save of an existing file in an editing session, preserve its previous
on-disk contents before overwriting it, for example as =filename~=. A new
file has no previous version to back up.

This is a planned feature, not implemented by the current editor. Saved-file
backups are distinct from auto-save/recovery of unsaved buffer edits.

** Current loading implementation

For now, loading an init file uses the installed =til run=: Tiled generates
a temporary entry point under this checkout's ignored =tmp/= directory,
imports the editor and user config, and compiles/runs them in a child
process. It removes that entry point, generated C and executable on return.
Keep the source checkout at its build-time location; this development
loader requires the installed compiler at startup. Lua-style in-process
embedding is tracked in [[https://github.com/jtimon/til/blob/master/issues/open/370.org][Til issue #370]].
