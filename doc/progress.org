** Internal splits

Default [[file:sessions.org][workspace persistence]] now restores files, recoverable unsaved text,
split/focus/history state and frame geometry. Both hosts use shared versioned
checkpoint I/O, writer locks and previous-generation recovery. Tiled has a Keep
exit action; terminal resources restore honestly as output/new-shell state.
Crash, corruption, concurrent-instance and discard tests pass on Linux.

=C-x t= now opens a terminal buffer using the same component as standalone
tilminal. Terminals participate in buffer switching and splits; hidden
sessions pump output and mirrored views share one resize owner. =C-x= remains
the host prefix, =C-x C-x= sends literal Ctrl-X, and other terminal input goes
to the child. Live-session kill/exit requires confirmation, while normal
child exit retains the final screen. [[file:terminal.org][Terminal tests]] cover this in real GUI
sessions, including remapped keys, large hidden output and child cleanup.

Primary-screen scrollback now retains 2,000 rows. Wheel and Shift+PageUp/Down
navigation have independent per-view positions, anchored output and return to
live on child input. Alternate screens stay out of history. Tests cover the
model, installed consumers and both hosts, including hidden and split views.

Both hosts now have linear mouse selection, selection-aware Ctrl-C, explicit
copy/paste and Ctrl-G cancellation. Copy joins soft wraps and preserves Unicode;
paste honors DEC 2004. Tiled text buffers have mouse/Shift/mark selection and
Emacs plus selection-aware CUA clipboard commands. Tests verify actual clipboard
contents, PTY paste bytes and per-pane routing. Selection persistence during
new terminal output and richer selection modes remain refinements.

Application sources live in =src/=: [[file:../src/tiled.til][startup]], [[file:../src/editor.til][GUI/input]], and
[[file:../src/editor_model.til][buffers/views/layout]]. =C-x 2= and =C-x 3= split the focused view;
=C-x o= changes focus, =C-x 0= closes a view, and =C-x 1= keeps only it.
The model supports multiple buffers, shared edits and independent points
and scrolling. =C-x C-f= opens a buffer in the focused pane; =C-x C-s= saves
it. Existing Ctrl+O/Ctrl+S bindings remain available.

[[file:../test/layout.til][Model tests]] check geometry, nested splits, traversal, subtree promotion,
shared edits, buffer isolation, cursor adjustment and node reuse. The
[[file:../test/splits.til][X11 integration test]] types split/focus/close sequences, edits from three
views of one buffer, saves and checks the exact file contents. It also
checks that closing the last view is refused and prefix keys do not enter
the document. It uses the same X11 dependencies as the keyboard tests.

#+begin_src sh
til run -o tmp/check_layout -c tmp/check_layout.c test/layout.til
til build -o tmp/check_splits -c tmp/check_splits.c test/splits.til
xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_splits
xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_splits remapped
#+end_src

Passing =screenshot= to =check_splits= additionally captures =tmp/splits.png=
using ImageMagick's =import=. This preview shows the nested panes, shared
contents, independent cursor locations and highlighted focus.
The =remapped= run uses =xmodmap= to swap left Control/Alt after the window
opens. Run it only on an isolated X server, as above. The same exact shared
buffer contents and successful exit verify the mapped prefix commands.

The nested-close test exposed a compiler lowering issue in installed Til
=0.0.1-2827886a4=: a vector lookup in a while condition was emitted before
the loop even though the body changed its index. The focus traversal now
performs that lookup explicitly in the body, re-reading the selected node
on each step. The sibling-subtree promotion case remains in the model test.

** Buffer commands and minibuffer

=C-x b= switches by name, =C-x C-b= lists buffers with current/modified
markers and filenames, and =C-x k= kills a chosen buffer. The shared
minibuffer filters choices, completes with Tab, selects with arrows, and
accepts Enter or cancels with =C-g=/Escape. Dirty-buffer deletion requires
the full =yes= confirmation; cancelling preserves the edits. Killing affects
every view of the buffer, without closing panes or writing/deleting files;
the last buffer is replaced by an empty draft buffer.

Per-pane history restores points/scrolling when switching. It is copied on
split, adjusted for shared edits, and pruned before a killed slot is reused.
Same-basename files have full-path choice names. The input bridge now queues
character callbacks alongside key callbacks to preserve order across prompt
transitions, even when a command, text and Enter arrive in the same frame.

[[file:../test/buffers.til][Model tests]] cover identity, hidden points, split histories, completion,
missing matches, confirmation, shared kills, draft replacement and reuse.
[[file:../test/buffer_input.til][GUI tests]] load two same-basename files through the existing =mode gui=
dialog, switch/edit/save in split panes, exercise cancellations and dirty
kills, then check exact file contents and last-buffer replacement. Both
normal and remapped-Control runs passed, as did the existing layout,
remapped-split, fast-quit and nine held-key checks.

#+begin_src sh
til run -o tmp/check_buffers -c tmp/check_buffers.c test/buffers.til
til build -o tmp/check_buffer_input -c tmp/check_buffer_input.c test/buffer_input.til

xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_buffer_input remapped
#+end_src

The GUI test additionally needs =zenity= (GTK's file chooser) and =pkill=.
=screenshot= captures =tmp/buffer-list.png= using ImageMagick; failed checks
attempt a screenshot at =tmp/buffer-input-failure.png= and include the app
log and X window tree. Run =remapped= only on the isolated test X server.

The test exposed an existing installed-Til dialog issue: in generated C,
=open_file_dialog= calls =tinyfd_openFileDialog= again when extracting the
result of its =switch=. Selecting a file therefore opens a second chooser
with Til =0.0.1-2827886a4=. The test answers repeated choosers; Tiled still
uses the =mode gui= helper.

** Save/discard/cancel on exit

=C-x C-c=, Escape in a text pane outside a prompt and the window's close button now share
one exit workflow. Every live modified buffer is prompted once, including
hidden buffers. Empty input defaults to cancel. Cancelling after an earlier
discard preserves that buffer's dirty state and text; cancelling after a
save retains the successful save. The layout and selected pane stay intact.
Live terminals offer terminate/cancel through the same sequence; all process
termination is deferred until acceptance completes. No modified text buffers
or running terminals means immediate exit.

An unnamed buffer uses the existing =mode gui= save dialog. Cancelling the
dialog or encountering a save error returns to editing rather than exiting.
The small [[file:../src/editor_save.c][save bridge]] reports open/write/close errors because installed
Til's =File.writefile= terminates the process on an open failure. Ordinary
save shortcuts use the same recoverable writer.

The first close-button test caught a queued-input race: checking
=WindowShouldClose()= before processing typed text could see a clean buffer
and exit. The GLFW close callback now queues a close request in key/text
order and clears the native close flag. The application makes the decision
after earlier edits have been processed. Repeated close requests preserve
the active exit prompt.

[[file:../test/exit.til][Model/save tests]] cover hidden dirty buffers, default cancellation,
repeated requests, cancellation after discard/save, successful writes,
open failure and a buffered write failure using Linux's =/dev/full=.
[[file:../test/exit_input.til][GUI tests]] exercise all three exit paths, empty/=C-g=/Escape cancellation,
save/discard, failed-save recovery, and draft save-dialog acceptance and
cancellation. [[file:../test/buffer_input.til][The buffer GUI test]] accepts =exit= to check multiple dirty
buffers, cancellation at the second buffer and saving a hidden buffer; this
also passed with remapped Control. Existing buffer, split, fast-quit and
held-key GUI checks passed.

[[file:../test/draft_save_gui.til][Draft Save As checks]] exercise the ordinary filename entry with suggested
=draft.txt= and a new filename containing spaces, cancellation without losing
text, and subsequent direct saves. The native result is captured once in
=src/file_dialogs.til= so matching it cannot reopen the chooser. Tests also
cover =draft_text= and the legacy =scratch_text= configuration alias.

#+begin_src sh

GUI dependencies are the same as the buffer tests (X11/XTest, =xvfb-run=,

** Mapped modifiers and fast prefix sequences

The old input loop paired queued =GetKeyPressed()= events with physical
=IsKeyDown()= modifier state sampled later in the frame. That ignored
=xmodmap= and missed quick chords when Control had already been released.

The [[file:../src/window_input.c][input bridge]] chains GLFW key and character-with-modifier callbacks and
queues each key press/repeat with its OS-mapped modifiers, alongside text
events. Prefixes and save/open shortcuts consume those event-time flags.
The bridge preserves raylib's callbacks for its own state and window handling.
C glue is needed because Til
function values use a closure ABI rather than GLFW's plain C callback ABI.

The reproducer is [[file:../test/quit.til][test/quit.til]], written in Til. It needs Linux/X11,
=xvfb-run=, =xwininfo=, Xlib development/link support and =libXtst.so.6=.
From the repository root, after building Tiled:

#+begin_src sh
til build -o tmp/check_quit -c tmp/check_quit.c test/quit.til
xvfb-run -a ./tmp/check_quit
xvfb-run -a ./tmp/check_quit fast
#+end_src

Both slow and =fast= quit checks now pass, along with normal/remapped split
sequences and nine held-key checks, including Control+Enter suppression.
Both quit runs close or
terminate their test application; its output goes to =tmp/quit-app.log=.

** Visible minibuffer under a decorating window manager

A real Xfwm4 reproduction explained reports that =C-x b= did not work and
the window would not close: =tile_left= requested a monitor-height client
area, then the window manager added a title bar. On a 1200-pixel display,
the client started at y=36 with height=1200, hiding the bottom input line.
Both the buffer chooser and live-terminal exit confirmation were active,
but their prompts were below the desktop.

Initial placement now uses GLFW's monitor work area and window frame sizes.
The pure Til placement policy subtracts decorations from the client size
and offsets its position. The complete frame fits the intended area, and
the buffer-switch and exit prompt input lines are visible.

[[file:../test/window_layout.til][Geometry checks]] cover decorated/undecorated windows, reserved panels and
non-primary monitor origins. [[file:../test/window_placement_gui.til][The GUI regression]] runs an actual Xfwm4 in an
isolated display/session bus, verifies the client lies within the desktop,
checks the prompt's rendered desktop pixels, switches buffers using remapped
Control, and accepts a visible close confirmation. A WM-free Xvfb alone
would not exercise the decoration bug.

#+begin_src sh
til run -o tmp/check_window_layout -c tmp/check_window_layout.c test/window_layout.til
til build -o tmp/check_window_placement_gui -c tmp/check_window_placement_gui.c test/window_placement_gui.til
dbus-run-session -- xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_window_placement_gui
#+end_src

The GUI check additionally needs =xfwm4= and =dbus-run-session=. It runs
without =--replace= and uses an isolated configuration directory. Failures
attempt a screenshot at =tmp/window-placement-failure.png=.

** Current limitations and next design work

- Init loading still compiles/runs a temporary child program. It does not
  embed an interpreter in the running host. Findings and acceptance checks
  were added to [[https://github.com/jtimon/til/blob/master/issues/open/370.org][Til issue #370]] for Lua-style embedding.
- An init path containing a double quote failed import resolution with the
  current compiler, despite escaping the generated string literal.
- [[file:keybindings.org][Named commands and contextual keymaps]] now support compiled Til callbacks
  and user overrides in both hosts. M-x completion/execution and describe-key
  now share the normal resolver/command executor. Live interpreted reload and
  a prefix suggestion menu remain planned.
- Multiple OS frames (=C-x 5=) and
  [[file:architecture.org][desktop hosts]] remain future work.
- Selection refinements, native platform
  validation and inline graphics remain [[file:terminal.org][terminal follow-ups]].
