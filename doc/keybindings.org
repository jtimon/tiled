** Startup keymap configuration

Both hosts resolve keyboard input through named commands and contextual
keymaps. Tiled's interpreted =~/.tiled/init.til= records overrides through
=tiled_bind= and =tiled_unbind= in its shared startup library. Tilminal's
compiled =~/.tilminal.til= uses =config.commands=. Overrides are applied to
the native default maps before opening the GUI.
See [[file:configuration.org][startup configuration]] and [[file:../defaults/tilminal.til][the standalone terminal sample]].

For Tiled, these lines in =init()= change terminal paste to plain Ctrl-V
and retain explicit forwarding of Ctrl-V to the foreground program:

#+begin_src til
tiled_bind("terminal", "C-v", "paste")
tiled_bind("terminal", "C-S-v", "forward-key", true)
#+end_src

A Tiled configuration using built-in commands (copy the binding import from
=gen/tiled_init.til=):

#+begin_src til
mode lib
import("/path/to/tiled/gen/tiled_startup_api")
init := proc() {
    tiled_bind("text", "F8", "save-buffer")
    tiled_unbind("text-selection", "C-x") // Always keep C-x as prefix.
}
#+end_src

For native host code, =config.commands.command(name, callback)= registers or
replaces a compiled callback; register before binding its name. Tiled's native
callbacks have signature =proc(mut EditorState)=
(pure =func= callbacks also work). Standalone callbacks have signature
=proc(mut Terminal, mut TerminalViewport)=. They borrow the receiving host's
live state for the duration of the call. Top-level functions can come from
imported modules. Callbacks may override built-in command names, except
=forward-key=, whose dispatch-bypass meaning is reserved.
Tilminal can still register these through its compiled init. Tiled's interpreted
init registers selected-text guest commands through =tiled_text_command(name, symbol)=.
Their callbacks have the checked signature =proc(Str) returns Str=; they receive
a snapshot and return a replacement. See [[file:tilvm.org][the live guest-command example]].
=tiled_command(name, symbol)= instead registers a zero-argument, no-result
command. It can use the [[file:live-buffers.org][live buffer API]] without a selection. Both kinds are
restricted to text context; general commands remain available when no region exists.

=tiled_bind(map, sequence, command, repeat=false)= replaces an existing binding.
=tiled_unbind(map, sequence)= removes it and its prefix descendants. The native
=config.commands.bind/unbind= methods have the same semantics.
=unbind(map, sequence)= removes it and any descendants of that prefix in
that map, exposing lower-precedence bindings. =ignore= consumes a key without
an action; =forward-key= bypasses host maps and sends the original event to
the terminal. There is no recursive key-to-key expansion.

*** Contexts and precedence

- Text: =text-selection= (when nonempty), then =text=, then =global=.
- Terminal: =terminal-selection= (when nonempty), =terminal-primary= (outside
  alternate screen), =terminal=, then =global=.
- Prompts: =minibuffer= only, so ordinary application commands do not leak
  into a prompt. =prefix= contains single-stroke controls checked first while
  a sequence is pending, such as =C-g= cancellation.

The first applicable map with an exact or prefix match wins each lookup.
Prefix continuations can fall back to lower maps. For example, selection-aware
Ctrl-C is a binding in =terminal-selection=; removing it restores child Ctrl-C
even while selecting. Rebinding only =terminal= does not override that higher map.

Sequences use spaces: =C-x C-s= or =F6 a b=. Modifiers are =C-= Control,
=M-= Alt, =S-= Shift and =s-= Super, taken from mapped event flags. ASCII
letters are case-insensitive in binding descriptions; express Shift explicitly.
Named keys include =Space=, =Enter=/=RET=, =Escape=/=ESC=, =Tab=, =Backspace=,
=Delete=, =Insert=, arrows, =Home=, =End=, =PageUp=, =PageDown= and =F1=..=F25=.
Character-key bindings beyond ASCII are not implemented yet.
This restriction is on shortcut descriptions, not [[file:unicode.org][Unicode text input]]:
documents, command names and minibuffers accept non-ASCII characters.

Consumed keypresses also consume their associated character events. Prefixes
have no timeout: a command, undefined continuation, cancellation or change of
focused pane/buffer/prompt ends them. An undefined continuation is consumed,
not replayed into the child. Repeats are opt-in for single-stroke bindings;
prefix controls and multi-stroke commands do not repeat. A key cannot be both
a command and a prefix in the same map: unbind the old subtree first.

*** Command discovery

=M-x= (Alt-X) opens a command palette in both hosts. Type part of a name or
binding, use Up/Down to choose, Tab to complete, and Enter to execute. Empty
or unmatched input keeps the prompt open; C-g or Escape cancels it. Built-in
and user-defined commands appear, including unbound commands. The adjacent
column shows effective bindings for the originating pane, including selection
and primary/alternate-screen precedence. Unavailable commands are labelled
and cannot be selected for execution; user callbacks supply their own behavior.

Palette acceptance feeds the chosen name into the same host command executor
as a keybinding. The accepting key's modifiers are not passed as editing
modifiers. =forward-key= requires an actual bound key event and cannot be
invoked by name. Prompts consume their own input without sending it to the
terminal or inserting it into the document. Opening M-x from an existing
minibuffer preserves that prompt and uses its context.

Run =M-x describe-key=, then press a key sequence. Tiled text panes also bind
=C-h k= to this command; terminal panes retain ordinary Ctrl-H input. Inspection
uses the normal resolver, reports the winning command and map or the unbound/
undefined disposition, and never executes the inspected action. Prefixes are
read until a complete binding or undefined continuation is reached. =C-g=
is the inspection cancellation key; Escape can itself be inspected. The result
appears in Tiled's status area (or the original prompt's hint), or in a temporary
tilminal footer. Selection/screen-mode changes are reflected when resolving keys.

Both discovery commands are ordinary named commands and can be rebound, e.g.:

#+begin_src til
tiled_bind("global", "F4", "execute-command")
tiled_bind("global", "F1 k", "describe-key")
// Restore Alt-X forwarding in terminal panes if preferred:
// tiled_unbind("global", "M-x")
#+end_src

*** Built-in command names

Text editing includes [[file:undo.org][branching undo and a tree browser]]: =undo=, =redo=,
=undo-tree-visualize=, =undo-branch-next= and =undo-branch-previous=.
=C-z=/=C-/= undo, =C-S-z= redoes, and =C-x u= opens the tree in text panes.

- Both hosts: =execute-command=, =describe-key=, =session-save=, =copy=, =paste=, =cancel-selection=, =scroll-page-up=,
  =scroll-page-down=, =forward-key=, =ignore=, =cancel= and =quit=.
- Tab commands in both hosts: =new-tab=, =close-tab=, =next-tab=, =previous-tab=,
  =move-tab-left=, =move-tab-right=, =toggle-tabs=, =show-tabs= and =hide-tabs=.
  See [[file:tabs.org][default shortcuts and lifecycle semantics]]. Tiled also has =hide-tab=,
  which removes a pane's tab reference without killing the underlying buffer.
- Tiled: =save-buffer=, =find-file=, =switch-buffer=, =list-buffers=,
  =kill-buffer=, =new-terminal=, =split-below=, =split-right=, =other-view=,
  =close-view=, =only-view=, =send-prefix= (literal Ctrl-X), =set-mark=, =cut=,
  =left=, =right=, =up=, =down=, =home=, =end=, =newline=, =backspace=,
  =delete=. Both hosts also have minibuffer navigation/acceptance commands
  (=accept=, =complete=, =previous-choice=, =next-choice= and cursor editing).

Commands still have appropriate contexts: buffer editing requires a text
buffer; prompt acceptance/completion requires a prompt; terminal scrolling
requires a terminal. Known but unavailable built-ins report a status message
in Tiled. Unknown command/map/key names and ambiguous prefixes are config
errors. The registered names and bindings are inspectable as
=config.commands.keys.names= and =config.commands.keys.bindings=. General
built-in command invocation from callbacks remains follow-up work. Tiled
callbacks currently receive editor state, not the native
terminal pool or prompt machinery. Mouse gestures remain host-defined.

Tiled interprets startup configuration and runs retained general/selected-text guest
commands in-process through TilVm. Tilminal retains the compiled loader and
needs installed Til plus the source checkout. General live editor APIs and hot
reload remain later milestones; see [[file:configuration.org][startup configuration]].

*** Verification

#+begin_src sh
./make.til
til run --usize=64 -o tmp/check_keymap -c tmp/check_keymap.c test/keymap.til
til interpret --usize=64 test/keymap.til
til build --usize=64 -o tmp/check_keymap_gui -c tmp/check_keymap_gui.c test/keymap_gui.til
xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_keymap_gui
til run --asan --usize=64 -o tmp/check_command_discovery -c tmp/check_command_discovery.c test/command_discovery.til
til interpret --usize=64 test/command_discovery.til
til build --usize=64 -o tmp/check_command_discovery_gui -c tmp/check_command_discovery_gui.c test/command_discovery_gui.til
xvfb-run -a -s "-screen 0 1600x1200x24" ./tmp/check_command_discovery_gui
#+end_src

The model checks map precedence, prefixes, repeat policy, unbinding, character
suppression and callback mutation. The GUI check uses an explicit native Tiled
fixture and tilminal's compiled user config, edits/saves a live buffer via a user command, rebinds prompt cancellation
and paste, checks bytes delivered to a PTY child, and rejects an unknown command.
Discovery tests additionally check effective bindings through shadowed prefixes,
selection precedence, command availability, rendered prompts/results, executing
unbound callbacks by name, nested prompt preservation and inspection without
file writes, application exit or terminal input leakage.
=test/init_gui.til= separately exercises the actual Tiled startup path, including
interpreted built-in bindings with the compiler unavailable on PATH.

** Future API sketch

[[file:keybindings.til][keybindings.til]] is the earlier, broader design sketch. Its =tiled= module
and exact API spelling remain proposals; the working API is described above.

Implementation is tracked in [[file:../issues/open/5.org][#5: Til-defined commands and configurable keymaps]]
for Tiled and tilminal, including the connection to Til interpreter embedding.

The starting combination is i3-style window management, Vim's =h/j/k/l=
directions, and Emacs-style named commands and editor prefix keys.

** Commands first

Interactive commands should be discoverable independently of keybindings.
Procedures defined in init code or imported files can be explicitly exposed
as commands; helper functions need not appear in the command list. A binding
is an optional shortcut to the same command, not what makes it callable.

- =tiled.command(name, procedure)= registers a zero-argument Til procedure as
  an interactive command. The example registers a terminal and a launcher;
  their external programs can be changed in the procedures.
- Built-in commands use the same registry. =execute-command= opens a prompt
  listing commands available in the current context and requests any arguments.
- =tiled.bind(keymap, keys, command_name, ...arguments)= records a command
  invocation; it does not run the command while loading the configuration.
  Arguments in this initial sketch are strings, validated by the command.
- =tiled.spawn(program)= starts a program asynchronously.
- =tiled.modifier("Super")= defines the =Mod= alias used in bindings.

** Command prompt and completion

=M-x= and contextual binding display are now implemented as described above.
=C-x C-c= and selecting =quit= through M-x use the same executor. Rich command
documentation and general argument-prompt declarations remain future extensions.

=C-x= is a keymap prefix, distinct from the command prompt. Optional
which-key-style hints could show its available continuations. Name-based
completion belongs in the command prompt. Suggestions should initially be
on demand rather than constantly appearing while editing.

** Keymaps and scope

- =wm= is active in window-manager mode. Its shortcuts operate on desktop
  windows; ordinary unbound input goes to the focused application.
- =editor= is active when a Tiled editor view has focus, in either application
  or window-manager mode. Its shortcuts operate on buffers and editor views.
  In window-manager mode, matching =wm= shortcuts take precedence.
- =resize= is a temporary desktop keymap entered with =Mod+r=. It captures
  input until =Return=, =Escape= or =C+g= leaves the mode. Unmatched keys are
  consumed in this mode rather than sent to the focused application.
- =+= joins simultaneous keys; spaces separate successive chords. Thus
  =C+x C+f= means Control-x followed by Control-f. =C= means Control,
  =M= means Alt/Meta, and =Shift= is explicit.
- Prefix sequences are inferred from bindings. =C+g= cancels a pending editor
  prefix; an invalid continuation cancels it and is consumed.

=split= prepares the placement of the next desktop window; =split-view=
creates another editor view immediately. A vertical divider places content
side by side, and a horizontal divider places it above and below.
=move-to-workspace= moves the focused window without switching workspaces.
=close-window= requests an application close; =close-view= removes an editor
view without discarding its buffer.

The editor supplies default [[file:configuration.org][bindings]] for splitting, focus,
closing views, open/save, buffer switching/listing and buffer killing. Its
minibuffer supplies filtering/completion and =C-g= cancellation for buffer
commands. See [[file:architecture.org][the buffer/window/frame model]] for =C-x 2= and =C-x 3=
behavior, and [[file:progress.org][progress]] for mapped-modifier and fast-prefix checks.
The broader command-prompt/window-manager API in this sketch remains a proposal.
