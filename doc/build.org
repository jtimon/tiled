* Building and running Tiled

[[file:../README.org][Tiled]] | [[file:configuration.org][Startup and configuration]] | [[file:keybindings.org][Keybinding design]]

** Requirements

Tiled currently targets installed Til version =0.0.1-b444d7223= (check with
=til -v=). The =til= executable must be on =PATH=, with its standard library
and GUI support installed. Til's native build also requires a C compiler.

Til's =make install= installs its support tree under =<prefix>/lib/til/=
(normally =/usr/local/lib/til/=). Core and the GUI prelude are loaded from
that tree automatically. Tiled uses =import("std/sys")= for system utilities.
Til's =std/= and =core/= prefixes resolve directly against the selected
compiler's support tree, independent of the application's directory and
without local shadowing. No explicit core import is needed for the types
and utilities already supplied by the core prelude.

This requires the natural-import support from Til issue #413. For genuinely
project-local modules named =std/= or =core/=, Til uses explicit relative
imports such as =import("./std/example")=.

The editor resolves its default monospace font through =fc-match= from
fontconfig. Install fontconfig and a monospace font, or set an explicit
=font_path= in your [[file:configuration.org][user configuration]].

=src/tiled.til='s =VERSION= constant follows Til's =0.0.1-<short git revision>=
pattern, computed at build time. Building it requires Git and a checkout of
this repository.

** Build and run

From the repository root:

#+begin_src sh
til interpret make.til
#+end_src

This builds =bin/tiled= and =bin/tilminal= sequentially, using
the installed compiler. Generated C goes under =gen/=. These build outputs
are ignored by Git. The proposed [[file:keybindings.til][keybindings.til]] configuration
is not built yet.

#+begin_src sh
./bin/tiled
./bin/tiled README.org
./bin/tiled -v
./bin/tilminal
#+end_src

See [[file:configuration.org][startup and configuration]] for init-file loading and scratch buffers.

** Issue summary

The [[file:../issues/process.org][file-based issue tracker]] follows Til's workflow. Regenerate
[[file:../issues/summary.org][issues/summary.org]] without building the GUI applications:

#+begin_src sh
til interpret make.til summary
#+end_src

This runs [[file:../examples/issues.til][examples/issues.til]] using installed Til. The generator groups open
issues by category and priority and checks metadata and cross-state number
collisions. New issue numbers come from =issues/NEXT_ISSUE.txt=.

** Source layout

- [[file:../src/tiled.til][src/tiled.til]]: startup, version reporting and user configuration loading.
- [[file:../src/editor.til][src/editor.til]]: GUI text editing, file open/save, cursor movement and
  line numbers. It is imported by [[file:../src/tiled.til][src/tiled.til]]; run =bin/tiled= to use it.
- [[file:../src/editor_model.til][src/editor_model.til]]: buffers, independent views and the split-layout tree.
- [[file:../src/minibuffer.til][src/minibuffer.til]]: reusable prompt text, filtering, selection and completion.
- [[file:../src/editor_buffers.til][src/editor_buffers.til]]: buffer choices, switching/listing and kill confirmation.
- [[file:../src/editor_exit.til][src/editor_exit.til]]: per-buffer save/discard/cancel exit state.
- [[file:../src/editor_save.c][src/editor_save.c]]: file writes reporting errors back to the editor, including
  buffered close failures, instead of terminating with unsaved buffers.
- [[file:../src/window_input.til][src/window_input.til]] and [[file:../src/window_input.c][src/window_input.c]]: the shared host GLFW callback bridge
  preserving key/text/close-request order and mapped, event-time modifiers. It links against Til's installed
  desktop raylib/GLFW backend; no Til checkout or GLFW headers are required.
- [[file:../src/tilminal.til][src/tilminal.til]]: standalone terminal with a persistent shell or one-shot command.
- [[file:../src/terminal/][src/terminal/]]: reusable terminal screen, text, PTY/ConPTY session and renderer.
  See [[file:terminal.org][terminal development and tests]].

The applications began in Til's =examples/= directory and are now developed
here. Tilminal's reusable terminal implementation replaces the old command
runner. Their =std/= imports resolve against the installed Til distribution's
matching support tree. Both applications use =mode gui=; embedded terminal
buffers in Tiled remain the next integration step.
