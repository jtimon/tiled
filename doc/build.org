* Building and running Tiled

[[file:../README.org][Tiled]] | [[file:configuration.org][Startup and configuration]] | [[file:keybindings.org][Keybinding design]]

** Requirements

The generated [[file:til-dependency.org][Til build dependency]] records the compiler used by the
last successful full build. The =til= executable must be on =PATH=, with its standard library
and GUI support installed. Til's native build also requires a C compiler.

The build driver is Til code: =make.til=, not a GNU Makefile. GNU Make is not
required to build this project. Unlike the Til compiler's own bootstrap,
Tiled assumes a working installed Til compiler and builds directly with it.

The =f24e6004c= upgrade passed both host builds, compiled/interpreted model
checks, ASAN checkpoint tests, installed-library consumers and all ten GUI
drivers, including the existing compiled user-config loader. No application
source changes were needed for this upgrade.

The earlier =3bcf0e933= upgrade exposed a compiler cleanup bug for an ignored managed return value followed
by an early return. The launchers now leave argument parsing to the actual
application entry point instead of redundantly discarding =SessionArgs.parse='s
result. =test/keymap_gui.til= covers both configured startup/shutdown paths.
Minimal compiler reproducer (run with =til run --asan= and a string argument):

#+begin_src til
mode cli
Result := struct { text : Str }
make_result := func(text: Str) returns Result { return Result(text = text.clone()) }
main := proc(args: ..Str) {
    make_result(args[0])
    if args.len() > 0 { return }
    println("unreachable")
}
#+end_src

Til's =make install= installs its support tree under =<prefix>/lib/til/=
(normally =/usr/local/lib/til/=). Core and the GUI prelude are loaded from
that tree automatically. Tiled uses =import("std/sys")= for system utilities.
Til's =std/= and =core/= prefixes resolve directly against the selected
compiler's support tree, independent of the application's directory and
without local shadowing. No explicit core import is needed for the types
and utilities already supplied by the core prelude.

This requires the natural-import support from Til issue #413. For genuinely
project-local modules named =std/= or =core/=, Til uses explicit relative
imports such as =import("./std/example")=.

The editor resolves its default monospace font through =fc-match= from
fontconfig. Install fontconfig and a monospace font, or set an explicit
=font_path= in your [[file:configuration.org][user configuration]].

POSIX application builds also require ncurses =tic= (usually supplied by
=ncurses-bin=). The build compiles =lib/libterminal/terminfo.src= into
=gen/terminfo/= and generates =gen/terminal_profile.til=. Both hosts set
child-local =TERM=tilminal= and =TERMINFO= to this absolute database location.
Keep the database available at runtime and rebuild after moving the checkout.
The =library= target does not require =tic= or package a terminal profile.

=src/tiled.til='s =VERSION= constant follows Til's =0.0.1-<short git revision>=
pattern, computed at build time. Building it requires Git and a checkout of
this repository.

** Build and run

From the repository root:

#+begin_src sh
./make.til
#+end_src

=make.til= is executable, with =#!/usr/bin/env -S til run=. The equivalent
explicit invocation is =til run make.til=; =til interpret make.til= also
works. In installed Til =f24e6004c=, =run= still translates and compiles the
driver on each invocation. The build script also invokes =til build= for the
library and both applications unconditionally. It does not yet skip host builds
when only tests change; incremental dependency checking remains future work.

=./make.til clean= removes =bin/=, =gen/= and =tmp/= from the repository
root. Rebuild afterwards before running the applications. Reference checkouts
live in Git-ignored =.inspirations/= (Emacs, Neovim, tmux, Ghostty and Conkeror), which
=clean= preserves. Treat =tmp/= as disposable scratch, not reference storage.

This builds =libterminal= independently and statically links =bin/tiled= and
=bin/tilminal= sequentially, using the installed compiler. Defaults are
=--cpu=baseline --usize=64 --opt=0=. Generated C, bindings and libraries go
under =gen/=. These build outputs
are ignored by Git. Tiled's interpreted init configures shared startup options
and built-in [[file:keybindings.org][keymaps]]; tilminal still supports compiled init callbacks.
The older =keybindings.til= API sketch remains a proposal.

#+begin_src sh
./bin/tiled
./bin/tiled README.org
./bin/tiled -v
./bin/tilminal
#+end_src

See [[file:configuration.org][startup and configuration]] for init-file loading and draft buffers.

** Library build modes

#+begin_src sh
til interpret make.til library --opt=2
til interpret make.til static --opt=2
til interpret make.til shared --opt=2
til interpret make.til source --opt=2
#+end_src

=library= builds the headless component only. =static= and =shared= select
Til-generated bindings to an explicit archive/shared-object path. =source=
is the whole-program control build used for comparison. The raylib view
adapter is still compiled with each GUI host. Static/shared staging currently
supports Linux; use source mode on other hosts pending packaging validation.

=gen/terminal_api.til= records the current selection and must be generated
before compiling a consumer or test. Shared binaries require the selected
library location to remain available; static executables do not load
=libterminal.so= at runtime. Til may still load its twin for compile-time or
interpreted evaluation. See [[file:../lib/libterminal/README.org][library API/install requirements]].

Full builds also compile =lib/libtiled/tiled_startup.til= as a shared library,
even when terminal linking is static or source-based. Tiled and its interpreted
init use the same explicit shared-object path via =gen/tiled_startup_api.til=.
=gen/tiled_runtime.til= records the matching SDK beside the selected installed
compiler (=<prefix>/bin/til= and =<prefix>/lib/til=). The build generates
=gen/tiled_init.til= as a ready-to-copy example with the binding path filled in.
The library-only terminal target does not build these startup assets.

At runtime Tiled needs that SDK's source assets, the generated binding and
shared library, but no Til/C compiler executable. The current development
layout uses build-time absolute paths; rebuild and update the config's binding
import if the build is moved. Tilminal's compiled init loader still needs the
compiler and source checkout. See [[file:configuration.org][configuration and migration]].

To use an already installed library rather than rebuilding its implementation:

#+begin_src sh
til install --cpu=baseline --opt=2 --usize=64 --prefix="$PWD/tmp/libterminal-install" lib/libterminal/terminal.til
til interpret make.til shared --opt=2 --lib-prefix="$PWD/tmp/libterminal-install"
#+end_src

[[file:terminal-library-benchmark.org][The linking comparison]] records parser, startup, memory and visible-output
measurements. It found no performance justification for a shared default;
hardware cache counters were unavailable on the test host.

** Issue summary

The [[file:../issues/process.org][file-based issue tracker]] follows Til's workflow. Regenerate
[[file:../issues/summary.org][issues/summary.org]] without building the GUI applications:

#+begin_src sh
til interpret make.til summary
#+end_src

This runs [[file:../examples/issues.til][examples/issues.til]] using installed Til. The generator groups open
issues by category and priority and checks metadata and cross-state number
collisions. New issue numbers come from =issues/NEXT_ISSUE.txt=.

** Source layout

- [[file:../src/tiled.til][src/tiled.til]]: startup, version reporting and user configuration loading.
- [[file:../src/editor.til][src/editor.til]]: GUI text editing, file open/save, cursor movement and
  line numbers. It is imported by [[file:../src/tiled.til][src/tiled.til]]; run =bin/tiled= to use it.
- [[file:../src/editor_model.til][src/editor_model.til]]: buffers, independent views and the split-layout tree.
- [[file:../src/minibuffer.til][src/minibuffer.til]]: reusable prompt text, filtering, selection and completion.
- [[file:../src/editor_buffers.til][src/editor_buffers.til]]: buffer choices, switching/listing and kill confirmation.
- [[file:../src/editor_exit.til][src/editor_exit.til]]: per-buffer save/discard/cancel exit state.
- [[file:../src/editor_terminal.til][src/editor_terminal.til]]: owning terminal pool, hidden-session pumping and
  the single resize-owner policy for mirrored panes.
- [[file:../src/editor_save.c][src/editor_save.c]]: file writes reporting errors back to the editor, including
  buffered close failures, instead of terminating with unsaved buffers.
- [[file:../src/window_input.til][src/window_input.til]] and [[file:../src/window_input.c][src/window_input.c]]: the shared host GLFW callback bridge
  preserving key/text/close-request order and mapped, event-time modifiers. It links against Til's installed
  desktop raylib/GLFW backend; no Til checkout or GLFW headers are required.
- [[file:../src/window_layout.til][src/window_layout.til]]: work-area/decorations-aware initial window placement.
- [[file:../src/tilminal.til][src/tilminal.til]]: standalone terminal with a persistent shell or one-shot command.
- [[file:../lib/libterminal/][lib/libterminal/]]: reusable terminal screen, text, PTY/ConPTY session and renderer.
  See [[file:terminal.org][terminal development and tests]].

The applications began in Til's =examples/= directory and are now developed
here. Tilminal's reusable terminal implementation replaces the old command
runner. Their =std/= imports resolve against the installed Til distribution's
matching support tree. Both applications use =mode gui= and the same terminal
component; Tiled embeds it through =C-x t= terminal buffers.
